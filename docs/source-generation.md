# Source generation and CK method clients

  - **Method clients:** `CkModelSourceEmitter` emits all sources of one model (records, types, enums); for every concrete type with methods (`CkTypeGraph.AllMethods`, own + inherited + interface) `MethodClientCodeGenerator` adds `Rt{Type}MethodClient` (one async method per CK method, wire contract of the asset repository's typed method mutations; naming rules in `GraphQlNames`). Runtime support: `Sdk.ServiceClient/AssetRepositoryServices/Tenants/Methods` (`CkMethodClientBase`, `CkMethodResult`, `CkMethodError`, `CkMethodCallException`, `CkMethodErrorReader`, `CkMethodTimeSpanSecondsConverter`). Declared errors → result, all other errors throw. Clients are emitted only when the compilation resolves `CkMethodClientBase` (`CompilationProvider`), so a DTO-only consumer or an older ServiceClient package keeps compiling. Types/models without methods: byte-identical output, gated by `MethodlessGeneratedCodeGoldenTests` (golden recorded before method clients existed). Schema gate: `MethodClientSchemaValidationTests` against the recorded SDL of the asset repository's integration-test tenant. Docs and fixture recording steps: `docs/method-clients.md`; migration guide skeleton: `docs/method-client-migration-guide.md`.
  - **Asynchronous methods:** a method with `execution.mode: async` gets a client method returning `CkMethodResult<CkOperationHandle<T>>` (`StartCkOperationAsync` on `CkMethodClientBase`, response base `CkMethodAsyncCallResponse`); its document selects `operation { … }` instead of `result`. `CkOperationsClient` (`GetOperationAsync`, `ListOperationsAsync`, `WaitForOperationAsync`, `WaitForCompletionAsync`, `CkOperationWaitOptions`, `CkOperationQueryException`) reads `runtime.operations` of the asset repository; kept off the generated client so no CK method name collides. Sync clients byte-identical: `SyncMethodClientGoldenTests` (`Fixtures/Golden/*.methodclients.golden.txt`). Async tests: `AsyncMethodClientTests` with System.Bot 3.7.0 (`Fixtures/ck-system.bot-3.*`) and schema/answers recorded on test-2. Docs: `docs/method-clients.md`, "Asynchronous methods".
  - **User method clients (option C):** the SDK ships **no** generated System.Identity surface (public API must not pin a model version). `tests/Sdk.SourceGeneration.Tests/Fixtures/ck-system.identity-3.*` (System.Identity 3.2.0 from the CK catalog) is generator input of `UserMethodClientTests` only (signatures, documents against `assetrepo-system-identity-schema.graphql.gz`, recorded `assetrepo-identity-answer-*.json`). `IIdentityServicesClient.AddRoleToUser`/`RemoveRoleFromUser` and `CreateUser`/`ResetPassword` (after octo-cli/octo-mcp-service switched) are `[Obsolete]` warnings, not errors (messages in `IdentityServices/UserMethodObsoleteMessages`, gated by `UserRestMethodsObsoleteTests`, which also pins the exact set of obsolete methods); they keep calling REST during their REST window. The SDK's own tests suppress `CS0618` locally with `#pragma` only where they test the REST wire format.
  - **Identity wave 2:** the fixture `ck-system.identity-3.*` is System.Identity **3.8.0** (compiler output of octo-identity-services), with the schema, wave 2 answers (`assetrepo-identity-answer-{group,client,role,api-scope,api-resource,data-permission,data-policy,external-mapping,email-domain-group-rule,identity-provider}-*.json`) and the System.Identity sync golden (generator of 7c48ed3) re-recorded; `IdentityWave2MethodClientTests` covers the 16 wave 2 clients (no client for the abstract `IdentityProvider`; one per concrete provider type). The 57 REST writes of `IIdentityServicesClient` they replace are **not** obsolete yet: as with the user methods, they become `[Obsolete]` in a follow-up change after octo-cli and octo-mcp-service switched, so their warnings-as-errors builds stay green. Migration guide: "Identity wave 2".
  - **Communication wave 3:** fixtures `ck-system.communication-4.*` (System.Communication **4.19.0**, compiler output of octo-communication-controller-services), `ck-system-2.yaml` (System 2.8.0, the dependency whose `Configuration` type 16 communication types derive from), `assetrepo-system-communication-schema.graphql.gz` and `assetrepo-communication-answer-*.json`; `CommunicationMethodClientTests` covers the 7 clients (30 client methods; no client for the abstract `DeployableWorkload`/`DeployableEntity`, their methods are on `Adapter`, `AdapterPool`, `Application`). The SDK ships no System.Communication surface. Compile tests of a model with cross-model bases use `GeneratorFixtures.EmitWithDependencies` (the dependency yaml emitted against the same cache, as for a consumer that also imports the dependency model). The replaced `ICommunicationServicesClient` methods get `[Obsolete]` only after octo-cli/octo-mcp-service switched.
  - **Cross-model DTO bases:** `AttributeCodeGenerator.BaseTypeDtoName` qualifies a base type of another model (`global::{root}.DataTransferObjects.{Model}.v{Major}.Rt{Base}Dto`); same-model bases and `System/Entity` (`RtEntityDto` of Communication.Contracts) stay unqualified. `GenerateMutationProperty` writes `[JsonIgnore]` only before a generated property, never before an `// Unsupported by Generator` comment. Tests: `CrossModelDtoGenerationTests`; the DTO goldens pin everything else.
  - Range-retaining models (CK v2, compiler default) reference dependencies major-qualified (`System@2/Name-1`) while the restored compile cache holds concrete ids (`System-2.5.0/Name-1`). `CkDtoModelBinder` binds the references to the cache before any DTO is generated (same step as the engine's model generator); a reference that stays unbound is reported as `OM1010`. Tests: `RangeRetentionDtoGenerationTests` (fixtures in `tests/Sdk.SourceGeneration.Tests/Fixtures` are real `octo-ckc Compile` output).

**Source Generation**
- Input: `ck-*.yaml` and `ck-*.cache.json` Construction Kit model files
- Output: `Rt{TypeName}QueryDto.g.cs`, `Rt{TypeName}MutationDto.g.cs`, enum classes, and `Rt{TypeName}MethodClient` (`{Type}MethodClient.g.cs`) for concrete types with CK methods
- Generated namespace: `DataTransferObjects.{ModelId}.v{Version}`
